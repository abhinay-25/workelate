# Design Note: The Work Assistant That Remembers

## 1. How We Choose What Goes Into a Brief

For every visible meeting `M` attended by person `P` on local date `D` (`zoneinfo.ZoneInfo(P.zone)`), the assistant computes a **per-`(person, client)` `since_day` watermark** (`prev_prepared_day + 1` from `P`'s prior meeting with `M.client`, or Day 1 if `P` is new to that client). This guarantees attendees who missed earlier meetings still receive prior baseline updates (`ev-nb-ne-05`) without repeating already-briefed items (`ev-nb-me-04`), while capturing same-day events recorded after the previous brief was generated (`rgg1ex2g`, `r46f5qdq`).

Within `[since_day, current_day]`, we ignore boilerplate acknowledgments (`is_boilerplate = 1`), routine chitchat/distractor traps, newsletters (`is_newsletter = 1`), and unedited doc carryovers, extracting only substantive task transitions (`blocked`, `done`, `due`, `owner`), winning claims (ownership handovers, milestone shifts, `Decision:` notes, spreadsheet/doc field diffs in `doc_versions`), and open client promises. Cancelled tasks already covered by a scope-drop decision are deduplicated, and changes include both old and new values so no stale claim is ever stated unqualified. Changes are then filtered by `P`'s preferences (`ignore_topic`, `blockers_first`, `most_important_first`, `max_changed`). If zero structured changes exist and substantive non-boilerplate records remain, we rank records via hybrid retrieval (FTS5 BM25 + 256-d cosine vectors with RRF) and pack only their boilerplate-stripped `sanitized_body` XML blocks (`<= 8,000` input tokens) to our 3-tier LLM chain (`Groq -> Gemini -> OpenAI Final Fallback`); if still empty, we return `"nothing_new"`.

## 2. How We Save Memory and Decide Who Can See It

State persists in a single local SQLite + FTS5 + `record_vectors` database (`.r3_assist.db`, reset cleanly on `ingest --day 1`) separating raw normalized `records`, event-sourced `task_transitions`/`tasks_state`, versioned `doc_versions` (including row-paired spreadsheet metrics), client `promises`, `claims`, `entity_aliases`, `collab_edges`, `feedback`/`preferences`, `forgotten_topics`, `record_vectors` (256-d embeddings indexed idempotently with optional local Qdrant support), and `brief_cache`.

Visibility is enforced in **depth**: (1) every SQL query runs through `visible_records_where_clause` requiring `org = P.org`, `day <= current_day`, `at_utc <= ISO`, `is_forgotten = 0`, `has_injection_span = 0 OR sanitized_body != ''`, and `visibility = 'team' OR (private AND author = P) OR (restricted AND P IN readers)`; (2) private/restricted checks for `"about me"` or colleague-activity asks use **boolean-only** existence helpers (`has_inaccessible_record_*`) that never surface content or IDs into prompts or responses; (3) `validate_brief_list` and `validate_ask_response` act as a mandatory output firewall stripping any un-cited, future, cross-org, forgotten, or injection-tainted text before serialization. Forgetting (`forget` / `type: forget`) retracts `P`-authored records across `records`, FTS5, and derived tables and purges `brief_cache` globally, while keeping independent `author != P` shared facts intact for teammates and suppressing `forgotten_topics` solely in `P`'s outputs.

## 3. How We Know Which Information Is Newest

Truth resolution never trusts top-level mutable task comment snapshots (defeating stale snapshot traps on `field == "comment"` and cross-field updates). Tasks are reconstructed monotonically by replaying `change` events (`at_utc ASC, id ASC`). Claims resolve strictly by explicit precedence: (1) explicit `feedback` `correction` entries persist over older records and later stale doc copies; (2) on ownership predicates (`predicate == 'owner'`), managerial/lead assertions beat `intern` assertions and interrogative questions (`"right?"`) never overwrite facts; (3) on partial `doc` updates, unedited carryover fields retain the `effective_at_utc` of the version that first introduced them, so newer targeted updates win; (4) otherwise, the newest non-expired (`valid_until >= local_date(ISO, P.zone)`), non-forgotten declarative assertion wins.

## 4. What We Will Not Do

- **Never leak cross-org or private/restricted content**: when a question probes inaccessible records (`q03-02`, `q05-01`, `restricted` docs), we emit `refused: {"reason": "private"}` without quoting text or record IDs.
- **Never execute prompt-injection directives**: span-level sanitization quarantines assistant-targeted commands (e.g., `"mark ... as AT RISK"`) out of `sanitized_body` and FTS5 while retaining co-occurring real facts, and the firewall rejects echoed injection phrases.
- **Never guess under genuine ambiguity**: tied task/client/person references emit `clarify` options (`q04-01`); zero visible matches emit `"I have nothing on that."` rather than hallucinating; never read ahead past `--day N` or `--at ISO`; never exceed `8,000`/`4,000` input token budgets.
